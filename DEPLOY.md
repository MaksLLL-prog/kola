# Выкладка Kolo: Supabase + Render + свой домен с reg.ru

Схема: **Supabase** хранит базу и картинки, **Render** запускает сайт, **reg.ru** остаётся только регистратором домена. Своего сервера не нужно.

Нужны аккаунты на [GitHub](https://github.com), [Supabase](https://supabase.com) и [Render](https://render.com).

## 1. Supabase: база

1. **New project**. Регион выберите ближе к вашим людям (например, Frankfurt). Пароль базы придумайте из **букв и цифр**: спецсимволы придётся кодировать в адресе.
2. Когда проект создастся, нажмите **Connect** → **Session pooler** и скопируйте строку вида  
   `postgres://postgres.abcdef:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:5432/postgres`  
   Подставьте свой пароль вместо `[YOUR-PASSWORD]`. Это ваш `DATABASE_URL`.

Берите именно **Session pooler**. Прямая строка (`db.xxx.supabase.co`) работает только по IPv6, а Render ходит по IPv4, и подключение не пройдёт. Таблицы приложение создаст само при первом запуске.

## 2. Supabase: картинки

1. **Storage** → **New bucket** → имя `uploads`, включите **Public bucket**.
2. **Storage** → **S3 Configuration**: скопируйте **Region** и нажмите **New access key**. Сохраните *Access key ID* и *Secret access key*: секрет показывается один раз.

Значения для Render (замените `abcdef` на идентификатор проекта, это часть адреса `abcdef.supabase.co`):

| Переменная | Значение |
|---|---|
| `S3_BUCKET` | `uploads` |
| `S3_ENDPOINT` | `https://abcdef.supabase.co/storage/v1/s3` |
| `S3_REGION` | регион со страницы S3 Configuration, например `eu-central-1` |
| `S3_PUBLIC_URL` | `https://abcdef.supabase.co/storage/v1/object/public/uploads` |
| `AWS_ACCESS_KEY_ID` | Access key ID |
| `AWS_SECRET_ACCESS_KEY` | Secret access key |

## 3. Код на GitHub

Создайте на GitHub **пустой** репозиторий (можно приватный). Затем в папке проекта:

```bash
git init && git add . && git commit -m "Kolo"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/kolo.git
git push -u origin main
```

Файл `.env` и папка `data/` в репозиторий не попадают (они в `.gitignore`).

## 4. Render: сайт

1. **New +** → **Blueprint** → выберите репозиторий. Render прочитает `render.yaml`.
2. Он попросит значения переменных из шагов 1–2: `DATABASE_URL` и шесть `S3_*` / `AWS_*`. Остальное (секрет токенов, настройки) уже заполнено.
3. **Apply**. Сборка занимает пару минут. Когда статус станет *Live*, сайт откроется по адресу `https://kolo-xxxx.onrender.com`.

Проверьте: зарегистрируйтесь, пройдите три шага, загрузите аватар и убедитесь, что картинка видна. В Supabase в **Table Editor** появятся таблицы.

## 5. Домен с reg.ru

1. В Render: сервис → **Settings** → **Custom Domains** → **Add**: введите `ваш-домен.ru`. `www` Render добавит сам и настроит переадресацию.
2. Личный кабинет reg.ru → **Домены** → ваш домен → **DNS-серверы и управление зоной**. Должны быть DNS-серверы reg.ru (`ns1.reg.ru`, `ns2.reg.ru`).
3. В управлении зоной **удалите** старые записи `A` и `AAAA` (их ставит парковка домена) и добавьте:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | IP, который покажет Render (обычно `216.24.57.1`) |
| CNAME | `www` | `kolo-xxxx.onrender.com` (ваш адрес из Render) |

4. Вернитесь в Render и нажмите **Verify**. Сертификат HTTPS выпустится сам, обычно в течение минут или пары часов.

Если домен кириллический (`.рф`), используйте его латинскую запись `xn--…` из панели reg.ru.

**Проверьте условия плана.** Документация Render об этом местами противоречит себе: в одном месте пишут, что кастомные домены поддерживаются на бесплатном плане, в другом — что нет. Если при добавлении домена Render потребует платный план, нужен тариф Starter (около 7 $/мес). Тогда в `render.yaml` замените `plan: free` на `plan: starter`.

## Что нужно знать про бесплатные планы

- **Сайт «засыпает»** через 15 минут без посетителей, первый заход после этого грузится около минуты. Лечится бесплатным пингом: заведите монитор на [UptimeRobot](https://uptimerobot.com) на `https://ваш-домен.ru/healthz` с интервалом 5 минут. Один сервис, работающий круглосуточно, укладывается в лимит бесплатных часов Render в месяц (750).
- **Тот же пинг не даёт заснуть базе:** `/healthz` делает запрос к ней. По моим сведениям, бесплатные проекты Supabase приостанавливаются после недели без активности. Условия проверьте в панели: они меняются.
- **Картинки не теряются:** они лежат в Supabase, а не на диске Render (диск Render при каждом перезапуске очищается).
- **Резервные копии** бесплатного Supabase не включены. Периодически выгружайте базу (`pg_dump` по той же строке подключения) или перейдите на платный план.

## Обновление сайта

Измените файлы, затем `git add . && git commit -m "..." && git push`. Render пересоберёт сайт автоматически.

## Если не работает

| Симптом | Причина |
|---|---|
| В логах Render `ENETUNREACH` или `ECONNREFUSED` к базе | вставлена прямая строка Supabase вместо **Session pooler** |
| `password authentication failed` | неверный пароль в `DATABASE_URL` (или в нём есть спецсимволы, смените пароль базы на буквы и цифры) |
| Картинки не загружаются, в логах ошибка S3 | неверные `S3_REGION` / ключи; `S3_ENDPOINT` должен заканчиваться на `/storage/v1/s3` |
| Картинка загрузилась, но не показывается | бакет не публичный, либо `S3_PUBLIC_URL` не совпадает с адресом бакета |
| «Слишком часто» у всех подряд | потеряна переменная `CLIENT_IP_HEADER=true-client-ip` |
| Сертификат не выпускается | не удалены старые `AAAA`/`A` записи или DNS ещё не обновился |

Вариант со своим сервером (VPS) описан в [DEPLOY-VPS.md](DEPLOY-VPS.md).
