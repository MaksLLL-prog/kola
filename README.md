# Kolo

Небольшая социальная сеть: лента с бесконечной прокруткой, репосты, закладки, хэштеги и «Популярное», личные сообщения, профили, подписки, комментарии с ответами, @упоминания и уведомления в реальном времени. Регистрация — в три шага.

**Стек:** Node.js 22+ · Express · SQLite (встроенный `node:sqlite`) или Postgres · JWT + bcrypt · SSE · чистый JS/CSS на фронте (без сборки).

## Возможности

- **Регистрация в три шага:** логин и пароль (имя проверяется на занятость прямо при вводе, индикатор надёжности пароля) → имя, о себе, аватар → подписка на людей. Аккаунт создаётся на первом шаге; пока онбординг не пройден, приложение возвращает человека на нужный шаг (флаг `users.onboarded`). Старые аккаунты считаются прошедшими.
- **Лента:** бесконечная прокрутка (IntersectionObserver, подгрузка по курсору), вкладки «Все» / «Подписки», баннер «новые посты» по SSE.
- **Репосты:** кнопка под постом, повторное нажатие отменяет. Репост — строка в `posts` с `repost_of`; в ленте и профиле показывается как оригинал с пометкой «Репост от …», счётчики общие. Автору приходит уведомление.
- **Закладки:** личный список `#/bookmarks`, в порядке добавления.
- **Хэштеги:** `#тег` в тексте становится ссылкой на `#/tag/тег` (регистр не важен, кириллица работает). Поиск по `#тегу` ведёт туда же.
- **Популярное:** `#/popular`, за неделю или за всё время. Баллы = лайки + 2·репосты + комментарии; сверху — тренды (теги). Тренды также в боковой колонке.
- **Дизайн (v2.4):** тёмный минимализм по референсу: фон #080C10, поверхности #12141A, тонкие границы, один фиолетовый акцент (#782CBF), скругления 8–12 px, круглые аватары, вкладки с подчёркиванием. Светлая тема — в меню слева и в профиле. На телефоне: записи на всю ширину, нижняя панель с «+», чат на весь экран. Системные шрифты, скелетоны, кэш ленты, мгновенные лайки, gzip, service worker.
- **Уведомления:** вкладки «Все / Ответы / Лайки / Подписки», превью поста, колокольчик со счётчиком в шапке, **push-уведомления** на телефон и компьютер (включаются на экране «Уведомления»), приложение можно добавить на экран «Домой» (PWA).
- **Фото в чатах:** скрепка, вставка из буфера, перетаскивание; фото уменьшается на устройстве перед отправкой; сообщение появляется сразу, при сбое его можно отправить повторно; просмотр фото на весь экран. Новый диалог — кнопка «карандаш» в «Сообщениях».
- **Личные сообщения:** `#/messages` (список диалогов, непрочитанные) и `#/messages/имя`. Доставка в реальном времени по SSE, счётчик в меню, отметка «прочитано», подгрузка старых сообщений при прокрутке вверх. Начать диалог — кнопка «Написать» в профиле. На компьютере Enter отправляет, Shift+Enter — перенос строки.

## Локальный запуск

```bash
npm install
npm start          # http://localhost:3000, база и картинки в ./data
```

## Продакшн (VPS + HTTPS)

Самый простой путь — Supabase (база и картинки) + Render (сайт) + домен с reg.ru: **[DEPLOY.md](DEPLOY.md)**. Свой сервер: [DEPLOY-VPS.md](DEPLOY-VPS.md).

Нужен сервер с Docker и домен, направленный на его IP.

```bash
cp .env.example .env     # заполните DOMAIN, POSTGRES_PASSWORD, JWT_SECRET
docker compose up -d --build
```

Caddy сам получит сертификат Let's Encrypt. Состав: `app` (Kolo), `db` (Postgres 16), `caddy` (HTTPS и прокси).

- **Бэкап базы:** `docker compose exec db pg_dump -U kolo kolo > backup.sql`
- **Обновление:** `git pull && docker compose up -d --build`
- **Картинки в S3:** заполните `S3_*` и ключи в `.env` (AWS, Cloudflare R2, MinIO и др.). Бакет должен отдавать файлы публично по `S3_PUBLIC_URL`.
- **Postgres без Docker:** задайте `DATABASE_URL=postgres://…` (и `PGSSL=1` для облачных баз), таблицы создадутся сами.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `PORT` | порт (3000) |
| `DATA_DIR` | папка с SQLite и загрузками (`./data`) |
| `DATABASE_URL` | если задана — используется Postgres вместо SQLite |
| `JWT_SECRET` | секрет токенов; в production обязателен |
| `TRUST_PROXY` | `1`, если сервер за Caddy/Nginx (нужно для лимитов по IP) |
| `S3_BUCKET`, `S3_ENDPOINT`, `S3_REGION`, `S3_PUBLIC_URL` | хранение картинок в S3 |

## Устройство

```
server.js    API, SSE, уведомления, сообщения
db.js        один интерфейс для SQLite и Postgres
storage.js   картинки: диск или S3
public/      index.html, style.css, app.js и dd
```

Уведомления идут по SSE (`/api/stream`), вход в поток — по одноразовому билету, JWT в адрес не попадает. Тип загружаемых картинок проверяется по содержимому файла.

## Push-уведомления

Работают только по **https** (на `localhost` — тоже). Ключи VAPID создаются сами и хранятся в таблице `kv`, поэтому переживают перезапуск. Чтобы задать свои: `VAPID_PRIVATE_JWK` (JWK приватного ключа P-256) и `VAPID_SUBJECT` (`mailto:вы@почта`). На iPhone push доступен только после «Поделиться → На экран Домой». Реализовано на встроенном `crypto` (RFC 8291/8292), без новых зависимостей.

## Ограничения

SSE-клиенты живут в памяти одного процесса: при нескольких экземплярах приложения нужен общий брокер (Redis pub/sub). Картинки не пережимаются. Сообщения не шифруются (лежат в базе открытым текстом), блокировки пользователей и удаления сообщений пока нет. «Популярное» считается запросом на лету — для большой базы понадобится кэш. Сброса пароля и подтверждения почты нет — для них нужен почтовый сервис.
